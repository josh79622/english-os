# CLAUDE.md

An English-learning loop. Claude Code generates a briefing, the learner
speaks it through with ChatGPT Voice, ChatGPT emits a Session Report, and
`ingest` turns that report into scheduled knowledge. Neither AI relies on
conversational memory; the repository is the memory.

Read [CONSTITUTION.md](CONSTITUTION.md) for what does not change,
[CONTRACTS.md](CONTRACTS.md) for the two locked AI interfaces, and
[MAINTENANCE_RULES.md](MAINTENANCE_RULES.md) for the health thresholds.

## Commands

```sh
npm run setup                 # briefings/COACH_SETUP.md   — paste 1 of 2
npm run briefing              # briefings/DAILY_BRIEFING.md — paste 2 of 2
npm run ingest -- <file>      # Session Report → items, schedule, metrics
npm run health                # H-checks; run after any change
npm run typecheck
npm run stats
npm run index                 # rebuild derived indexes
```

`typecheck` and `health` should both be clean before you commit.

## Where things live

| Path | |
|---|---|
| `knowledge/items/` | The knowledge base. One item per file — source of truth. |
| `knowledge/PROFILE.md` | Hand-written facts about the learner. Not derived. |
| `sessions/<year>/` | Raw Session Reports, written by ingest. Immutable. |
| `briefings/`, `state/`, `knowledge/INDEX.md` | **Derived.** Safe to delete. |
| `src/` | The tooling. |

## Things that will bite you

**Do not edit `briefings/*.md`.** They are regenerated by
`src/briefing.ts` on every briefing run and on every ingest. Prompt
changes go in `renderSetup()` / `renderBriefing()`.

**`DAILY_BRIEFING.md` must stay under ~2000 characters.** Past that,
ChatGPT converts the paste into a file attachment and reads it as a
document to review — it summarises the briefing back and offers to
improve the phrasing instead of starting the session. This has happened.
Everything that does not vary per session belongs in `COACH_SETUP.md`,
which is pasted first and may safely arrive as an attachment.

**`src/schedule.ts` is the only place that decides dates.** ChatGPT
grades; it never computes a next review.

**`today()` is local time, `toIso()` is UTC.** Both are commented in
opposite directions in `src/util.ts`. `toIso` exists for `addDays`, which
anchors at UTC midnight so date arithmetic never meets a DST boundary.
Do not unify them.

**`## Off limits` in PROFILE.md is not a normal section.** It still
reaches the coach — a coach that does not know cannot avoid it — but
renders under its own instruction to steer around rather than towards.
Everything else in the profile renders as fair game.

**Scenario personas are keyed per scenario, not per domain.** Pooling
them by domain once produced a supermarket checkout operator taking a
dentist booking.

**A malformed Session Report should stop the ingest.** Never loosen the
parser to accept one. A silently misread report corrupts the knowledge
base in ways that are very hard to notice later.

## Working on the prompt

Everything in the coach prompt is there because a session failed without
it: the coach going passive, summarising the briefing instead of starting,
interrogating the learner about facts he was never given, inventing item
ids he had never been shown. Before deleting a rule, check `git log` for
the commit that added it — the reasoning is in the message.

Compression is not free. Squeezing the setup into ChatGPT's Custom
Instructions was tried, fit in 1332 + 1572 characters, and was reverted:
the rules it cut each cost a dead session to learn.
